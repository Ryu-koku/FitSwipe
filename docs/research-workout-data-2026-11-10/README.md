# 筋トレのデータ表示調査とFitSwipeへの提案

確認日: 2026-11-10。

FitSwipeでは、**「前回と比べて何が変わったか」「次に何を目指せるか」「今週どこまで実施したか」を、同じ条件で説明できる表示**を先に充実させることを提案する。これは競合比較と現行コードからの設計判断であり、継続率や筋力向上への効果を実験で順位付けした結論ではない。

保存されていた4分野の調査を引き継ぎ、空白領域を追加探索した。324件の観察・案を、16分野・270の表示テーマに統合した。元の観察と細部はすべて保持している。「テーマ」には数値指標だけでなく、比較条件、欠測、計画、表示する時点、根拠を開く操作も含む。270個の独立した身体計測値という意味ではない。

## 読む入口

- [検索・絞り込みできるレポート](report.html): 必要データ、優先度、分野、競合名で探索できる。表示例は架空データによる提案。
- [全270テーマの一覧](catalog.md): 各候補の用途、入力要件、制約、出典、元の観察ID。
- [CSV](catalog.csv): 表計算用。UTF-8 BOM付き。
- [JSON](catalog.json): 全324観察を`variants`に保持した統合データ。参照リンク179URLを収録。
- [引き継ぎ記録](HANDOVER.md): 元の依頼、完了したUI修正、現在の検証状態。

## 通常画面へ置く量と、深く見る情報

**記録中**は、今の重量・回数を大きくし、近くに前回の同条件セットと今回の小さな目安を置く。1タップで日付・全セット・グラフを確認できる構造が合う。余力を導入するなら、セット後に任意で答える短い入力から始める。e1RM、累積量、順位、回復点を同時に常時読ませる必然性はない。

**終了直後**は、完了したことと1〜2件の具体的な変化を示す。自己ベストがなくても同重量+1回、期間内の改善、継続を拾う。スキップ、目標未達、成功0回の試技は別の状態として扱う。今日の記録の確認・修正もここで完結させる。

**ホーム/週の振り返り**は、週の実施状況、直近の改善、次の予定を入口にする。今週途中を先週全体と比較しない。完了週同士、同じ曜日まで、同じ長さの直近期間を切り替え、何対何かを見せる。週目標や部位目標は本人が選べるようにする。

**種目の詳細**では、実測重量、同重量の回数、回数別PR、期間PR、推定最大重量、全セットの分布、条件タグを探索できるようにする。グラフの点は元セットへつなげ、プログラム変更やdeloadなど記録の文脈を付ける。

**専門の詳細**は、速度・ROM・パワー・フォーム動画・力・EMG/SmO2など、実際に取得しているデータがある人へ提供する。入力のない空の指標を大量に配置する必要はない。

## 入力の負担と優先度

完全なテーマを実現するための条件で分類すると、既存記録から集計できるもの68、追加の任意入力・設定・保存が必要なもの118、撮影・機器・ヘルス連携が必要なもの78、外部基準が必要なもの6。単純な変種は少ないデータで作れるため、各行の制約も読む。これは実装済み機能数ではない。

優先度はP0=今のログで着手する21テーマ、P1=入力/計画保存等の土台を整える37テーマ、P2=対象者・目的別の拡張128テーマ、P3=計測/外部基準を要する専門機能84テーマ。これは本アプリ向けの設計判断であり、全利用者の需要を調査した順位ではない。

**第1段階**では、入力を増やさず「前回/同条件/期間/元記録/欠測」を整える。現行の重量・回数・e1RMグラフを活かし、同重量フィルター、実測RM、期間PR、分母付き週比較を追加する。既に存在する機能は表示と説明を改善する。

**第2段階**では、必要な人へ任意RIR、セット種別、機材設定、メモ、本人の週目標を足す。同時に、計画と実績を別保存する。入力したデータが直後の前回比較や次回準備に返ってくることを重視する。

**第3段階**では、種目選択・目標・機材が明確な人へ提案と理由、部位別目標、ブロック比較を出す。推定できないケース、適用範囲、手動修正を同時に用意する。

**第4段階**では、要望がある対象へ動画・VBT・ウォッチ・コーチ共有・競技/技能を追加する。一般ユーザーのために力積やEMGを標準ホームへ置く優先性は低い。

対象はExpo版の`mobile/src`。確認した主なファイルは`types.ts`、`logic.ts`、`home-progress.ts`、`workout.ts`、`app/workout.tsx`、`app/growth.tsx`、`components/HomeProgress.tsx`、`components/SessionDetails.tsx`。

| 外部データが必要 | 速度/ROM/力、心拍/HRV/睡眠/歩数、身体組成機器、競技結果、比較母集団 | 取得元と計測/推定方法を保存する |

`setOrder`は種目内の順序。進行中の`exerciseOrder`を、完了後の実施順の完全な記録とは扱わない。`presetId`は過去の計画のスナップショットではない。`createdAt`/`updatedAt`は挙上時刻や実休憩ではない。特に「当初の計画達成率」「後半だから落ちた」「休憩が短かった」を今のログから正確に復元しない。

将来の保存項目は、(1)開始時の計画と版、(2)実施した値と状態、(3)アプリ上の操作/タイマーのイベント、(4)比較条件、(5)外部データの由来、を別に扱うと分析しやすい。操作時刻も人が押した時刻なので、センサーが測った挙上時間とは区別する。

## 集計・言葉の定義で体験を壊しやすい点

| 指標 | 表示する定義・限界 |
|---|---|
| 外部負荷量 | 完了した各側の重量×回数の和。`kg×回`の慣用的な量で、力Nや仕事Jではない。自重種目を0の成果と表示しない |
| 自重/補助/加重 | 種目の体重寄与、補助を引くか、片側入力を倍にするかで変わる。機器のkgも自由重量と同じとは限らない |
| 部位セット | 主働筋1/副働筋0.5等は配分モデル。Hevyの筋群別ヘルプはWUを含むと説明し、別の設定ページには総セット/量/PRへWUを含める切替がある。対象画面・設定を添え、一律の共通値にしない |
| 推定最大重量 | FitSwipeは1回を実測値、2〜10回を`重量×(1+回数/30)`とし、11回以上は対象外。RIRやROMの補正はない。実測最大や筋肥大量と呼ばない |
| 期間PR | 全期間、今年、選択期間、復帰後は別の問い。初回基準・前回比・自己最高を別扱いにする |
| BIG3 | 現行集計は対象3種目の全期間最大e1RMの和。同一大会・同一日の実測Totalとは違う |
| 時間/密度 | 終了−開始は中断/準備/休憩を含む。量÷分はそのセッションの記録密度であり筋肥大効率ではない |
| RIR/RPE | セットの余力、全体のきつさ、痛み、パンプ、筋肉痛を別質問にする。未回答を0にしない |
| 回復/準備/strain | ベンダー独自の計算。ログ由来の局所回復、HRV等由来の全身状態、心血管負荷、量を区別する。メーカー間の100点を交換可能な単位にしない |
| MQ/FS等の名称 | TonalのMQ/FSは、その目標を鍛える内容に割り当てた点の週集計。本人のフォーム品質を直接測った結果とは別 |
| 脂肪/除脂肪量 | 体重と体脂肪率から計算した値、BIA等の機器推定、周囲径、写真は由来が違う。除脂肪量には筋以外も含まれる |
| 順位/レベル | 比較母集団、集計期間、競技/練習、体重/年齢等の条件、件数、記録の失効を明記。アプリ利用者の分布を一般人口の順位にしない |
| センサー値 | 平均/最大、求心/遠心、単位、装置、採用/除外、撮影条件を揃える。バーROMと関節ROM、入力の左右差と実際の力配分を分ける |
| 変化の理由 | 計画変更・睡眠・食事・周期等との前後関係は振り返りの材料。個人の因果や故障の原因を断定しない |

計算条件の実例は[Hevy](https://help.hevyapp.com/hc/en-us/articles/44128140257431-How-Does-Sets-per-Muscle-Group-Work)、[Strong](https://help.strongapp.io/article/166-set-tags)、[MacroFactor](https://help.macrofactorapp.com/en/articles/275-getting-to-know-your-workouts-dashboard)、[Tonal](https://knowledge.tonal.com/kb/guide/en/how-to-use-personalized-weekly-targets-IcOTXeWcYl/Steps/4353081)、[Dr. Muscle](https://dr-muscle.com/new-dr-muscle-x-2026/)を参照。

## 調査の到達点

最初に一般的な記録アプリを横断し、次に適応処方・主観・回復・ブロック、日本語アプリ・自重・身体変化、速度・力・動画・専門計測へ広げた。統合前の各ノートには複数回の深い探索と未確認項目が残っている。

引き継ぎ後は、サーキット、競技試技、種目間レベル、クライミングの試行と条件、任意の周期記録、セット種別を追加。さらにprogrammingの分布、専門の力/酸素計測、集計設定を狙って確認した。最後は既存分類内の尺度・粒度・条件差が中心になり、本文だけにあった食事・歩数・kcal・身体組成・XP・目標別スコアも回収した。

公開Web調査で「世界に新しい表示が絶対に残っていない」ことは証明できない。今回の完了条件は、筋トレの体験に関係する取得データ・判断・比較条件の分類を埋め、狙った追加探索が既存の系統へ収まる状態まで進めること。全実機、段階配信、非公開企業向け画面、将来機能には未調査部分がある。

前セッションが確認した保存資料を土台に、引き継ぎ後に重要な定義と追加分の主要ページを再確認した。Garmin/Appleの一部は検索本文による補完、Perchは公式ブランドのバックアップサイト、ストア説明は開発者の主張という違いがある。本文取得に失敗した資料やプレビューを、現行機能の確証へ格上げしていない。無料/有料の網羅比較や価格調査はしていない。

需要の根拠として残る公開フィードバックは少数の自己選択例であり、市場全体の優先順位を示さない。P0候補を触れる形にした後、記録中の迷い、比較の理解、次回の準備、入力にかかる時間で利用者テストするのが次の検証になる。この調査では製品への追加実装は行っていない。

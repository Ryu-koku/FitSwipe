# 種目イラストと動作ループ

2026-11-10 の赤ペン回答を反映。既存の黒い人物・アイボリーの輪郭・赤い対象筋の絵柄を使い、初期カタログ57種目を個別に描く。

## 調査で分かった欠落

旧 `ExercisePictogram` の対応は4画像だった。初期57種目のうち画像に到達した名前は3件で、54件は汎用ダンベルになっていた。3件のうちインクラインダンベルカールには、部分一致により立位のカール画像が割り当てられていた。ペックフライ／サイドレイズは、既存画像のラベルと一致せず表示されなかった。追加一覧とメニュー行には画像自体がなかった。

## 採用した表示

- トレーニングのメイン画像、種目の追加一覧、メニューの種目行に表示する。
- 関節と器具の位置を変えた16姿勢を、3.2秒の WebP ループで再生する。一覧とメニューでも自動再生する。
- 小さい画像を押すと拡大する。種目の選択や編集は種目名側で行う。
- 画面外、別画面、アプリの非表示、拡大表示に覆われた画像は 静止画に切り替える。端末の「動きを減らす」が有効、または設定が未取得の場合も静止表示する。
- プランクは姿勢を保つ種目なので静止画にする。ランニングは往復を反転せず、一歩の周期を描く。
- 全素材をアプリに同梱する。未知のカスタム種目名には汎用アイコンを使う。

## 対応表と素材

`mobile/src/exercise-visuals.ts` が名前を NFKC 正規化し、正式名と明示的な別名だけを照合する。`mobile/src/data/exercise-visuals.json` が表示用の対応表、`mobile/src/exercise-visual-assets.ts` が Metro の静的 require 一覧。

通常／インクライン、マシン／フリーウエイト、順手／逆手を別素材にする。旧ラベルの「ペクトラルフライ」「ダンベルサイドレイズ」も正式な別名として解決する。

最終素材は `mobile/assets/exercise-motions/`。`<key>.webp` が動作、`<key>-poster.webp` が停止時の表示。プランクには静止画だけを用意する。

完成素材は56ループ＋57枚の静止画で合計約15.0 MB。当初は320px・静止画PNGで約30.2 MBだったため、2026-11-10 の赤ペン回答で240px・静止画WebPに下げた。コマ数と全同梱は維持する。

## 制作と更新

画像は組み込みの imagegen で種目ごとに生成した。参照画像は `mobile/assets/dumbbell_curl.png`。生成の指定は `scripts/exercise-visuals/definitions.json` の器具・姿勢・視点と、`prepare.py` の共通プロンプトに保存する。

```sh
python3 scripts/exercise-visuals/prepare.py --requests
python3 scripts/exercise-visuals/prepare.py --key bench-press --source /path/to/generated.png --ffmpeg /path/to/ffmpeg
```

`--requests` はプロンプト一覧を `output/exercise-motion-sources/requests.json` に出力し、表示用の対応表と require 一覧を生成する。imagegen は各リクエストを個別に実行する。画像の切り出し・縮小・形式変換だけを ffmpeg で行う。Pillow は入力のサイズとアルファの検査に使う。

生成された原画・各回のプロンプト・パッケージ情報は、作業ディレクトリの `output/exercise-motion-sources/` に保持する。原画は4列×4行。最大240px、200ms×16フレーム、無限ループに変換する。静止表示には中間姿勢を使う。

## 検証

`mobile/test/exercise-visuals.test.cjs` が初期57種目の網羅、別名と派生種目の分離、未知名、再生条件、画面との交差、実ファイルと WebP のフレーム時間・ループ設定を検査する。

React Native Web の一時ハーネスでは、実際の画面とコンポーネントを使い、再生・停止・拡大・選択・スクロール・ライト／ダーク表示・横幅320pxを確認した。結果とスクリーンショットは `output/exercise-visuals-preview/` に保存する。これはネイティブ端末での確認とは別で、接続された実機はなかった。

最終確認ではテスト167件成功、既存の外部サービス連携テスト1件はスキップ。型検査成功、Lint はエラー0件・既存警告1件。Android 向け `expo export` は1847モジュールと全113素材を含めて成功した。これはAPKの生成・インストールとは別の検証。

`expo-image` を追加しているため、既存の開発アプリではネイティブ部分を含む再ビルドが必要になる。
